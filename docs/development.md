# Development and validation

```sh
npm run typecheck
npm run lint
npm run test:quick                           # seconds: the core tests, after every step
npm run test:quick -- tests/cobweb.test.ts   # plus the test file of what you are changing
npm test
npm run validate:exports
```

The tests check schemas, duration rounding, presets, determinism per seed and motion continuity where cycles meet. For the overlays, they also check the size table (even, file = box + 2·bleed), the stroke geometry, periodicity at several sizes, at 50 and 60 fps and with odd durations, the borders' empty window, the bleed, legibility over the text, each theme's presets, the file names, the position JSON and pack planning, all without rendering. The ornaments have their own tests: `tests/ornaments-harness-<set>.test.ts` runs each set through every size of the three kinds (and the kits' presets, also as the pack renders them), with the shared engine in `tests/helpers/ornament-harness.ts` (`cobweb` splits the borders into `-cobweb-border`, to run in parallel); `tests/ornaments.test.ts` covers the engine's rules; and `tests/ornaments-midnight.test.ts`, `-haunted-mansion`, `-haunted-interior` and `-cobweb` check each set's motifs against the source background (drawings, colors and rhythms). Export validation produces real samples at full resolution and inspects codecs, dimensions, duration/FPS, GIF repeat, the MOV's ProRes 4444 profile and the alpha of WebM, MOV and PNG.

`tests/markup-snapshot.test.ts` is the regression guard for drawings: it hashes the scene and the rendered markup of the four Halloween backgrounds and of every file of every pack in `packs/` (frames 0 and 123, with the props the pack plan exports), and compares them with the versioned baseline in `tests/__snapshots__/markup.json`. Any change to what a file draws fails it, naming the files. When the change is intended, regenerate the baseline and commit its diff with the change: `UPDATE_SNAPSHOTS=1 npx tsx --test tests/markup-snapshot.test.ts`. A refactor that should draw the same keeps the baseline untouched.

That step needs full FFmpeg and FFprobe on the `PATH`, or in `FFMPEG_PATH` and `FFPROBE_PATH`: the FFmpeg bundled with Remotion lacks the `rawvideo` muxer, used to decode the first frame, and reading WebM alpha needs the `libvpx-vp9` decoder.

For backgrounds, there are four 0.4-second samples per composition: MP4, opaque WebM, WebM with alpha and GIF. For overlays, there are WebM, MOV and PNG with alpha and a composited MP4, at the smallest and the tallest catalog size of each kind. To validate only part of it, use `--kind` with `background`, `chat`, `block` or `border`, and `--only` with part of the sample's name (`npm run validate:exports -- --kind block --only label-sm`). The report in `out/.scratch/validation/report.json` (another folder with `--out <folder>`) records each approved file, including the comparison of the first decoded frame with a fresh Remotion PNG, composited over light and dark backgrounds. For longer samples, use `npm run validate:exports -- --duration 8`. To resume an interrupted check without repeating the existing encodes, add `--reuse-existing`: present files are inspected again and missing ones are rendered. After changing animations or export presets, run without that option to produce fresh files.

An ornament set lives in `src/overlays/shared/ornaments/sets/` and follows a contract these tests enforce. `place` picks positions and sizes from the layout and `ornamentSize` only, with no seed or frame, main motif first; an empty list becomes the refusal with the way out. `build` returns, every frame, the same number of flat elements, each inside the circle of its position (light included), with motion in whole harmonics of the cycle and at most 0.2 of light over the text. `render` draws with no `filter` or blend mode. No motif goes past the bleed or into the text area or the window. `npm run ornaments:report -- <pack>` prints, without rendering, where the sets put their motifs on every file of a pack: each motif's slot, layer, size, extent and the room at its spot, and the motifs a file drops that other files of the same kind keep.

Visual verification is `npm run stills -- <job.json>` (format in `scripts/stills-job.ts`): stills, contact sheets, stream mockups, loop seams, determinism, before/after against a git ref, region stats and `report.json`, in `out/review/<date>-<job>/`. A whole pack is `npm run qa:kit -- <pack>`. Pixels are measured with `npm run stills -- inspect` (region, profile, crop, diff; `--help` lists the definitions), never with a throwaway script.

To validate a visual change, play at least two cycles in the Studio. Look especially at the seam, the edges, shadows, colors and the composition over light and dark backgrounds when there is alpha. Different durations and seeds must keep the loop continuous.

## Adding an asset

1. Pick the kind in `src/kinds.ts`: it sets the Studio folder, the size and the initial value of `transparent`. A kind may have several compositions (for example, a themed border next to `BorderLoop`); a new kind needs the full policy and, if it has a free size, the sizes in `src/sizes.ts`.
2. For a background, create the component in `src/backgrounds/` and extend `baseBackgroundSchema`. For an overlay, create it in `src/overlays/<kind>/`, build the schema with `overlayBaseFields(getSize(<default size>))` and the groups in `src/overlays/shared/fields.ts` (fill, stroke, glow, halo), and finish with a `superRefine` that calls `refineCanvas`, `refineOutset` and the kind's refusals, always with the way out in the message. Decorative measures stay in fixed px.
3. Split the visual computation into a pure function that takes props, frame and total frames and returns a flat list of elements, each with a numeric `opacity`, listed by slot so the swaps do not show at the seam. Use `loopPhase` and the seed for periodic, reproducible motion, and, on the stroke, `fitPeriod` and `lapsFor`; avoid the clock, `Math.random()`, CSS animations or state accumulated between frames.
4. In an overlay, also write `getLayout(props)`, pure and the single source of geometry: `canvas`, `box`, `content`, `hole` (borders), `header` (if any) and `outset`, which never goes past the bleed. Add `getMotion` for the actual speed and, if the asset has a mask, `getMask`.
5. In the component, read `useCurrentFrame()` and `useVideoConfig()`, draw the function's result and use the same background rule as the existing compositions (`hasAlpha`; in overlays, `OverlayCanvas`).
6. Register the entry in `src/catalog.tsx` (`backgroundCatalog` or `overlayCatalog`) with `id`, `kind`, `component`, `schema`, `defaultProps: schema.parse({})` and, for overlays, `getLayout` and `getMotion`. In `src/Root.tsx`, add the `Composition` inside `<Folder name={kindPolicies.<kind>.folder}>`, with `id="Name"`, a literal object in `defaultProps` so the controls can be saved in the Studio and, for overlays, the examples' `calculateMetadata`, which makes the Studio canvas follow `width`, `height` and `bleed`. The exporter reads the composition's effective defaults and applies only the requested overrides.
7. Add presets in `presets/` (for overlays, `presets/<kind>-<theme>.json`, with no fixed size, valid against the strict schema at every size of the kind) and, if needed, the item in the pack manifest; a new theme also goes into `tests/helpers/themes.ts`: into `CLASSIC_THEMES` if it uses neither ornaments nor lightning, or into `KIT_THEMES`, named `halloween-<set>`, if it uses that set's ornaments; the Twitch panel item in the pack may only carry the keys `transparent`, `paddingX` and `paddingY` in `props`. The list feeds the overlays' preset, pack and loop tests.
8. Include the scene in the generic sweeps of `tests/backgrounds.test.ts` (determinism per seed, periodicity at `N`, speed at the seam, with `seamExempt` when needed, and valid values) and write its own tests: periodicity at several sizes and FPS, refusal at the speed limit, bleed respected, text area and window. `tests/overlay-registry.test.ts` checks the link with the Root, the presets, the layout and the names. Validate the seam in the Studio and render a sample in the formats you need.

`src/settings.ts` holds the alpha rule, the metadata and the export presets; `src/kinds.ts` and `src/sizes.ts`, the kinds and the sizes. Keep the Remotion packages at the same exact version and keep the lockfile for reproducible installs.
