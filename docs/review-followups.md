# Review follow-ups

Findings of a review that did not block its change, kept here until someone takes them on. Remove an item once it is done.

- `validate:exports` samples every catalog composition per kind, so a full run or `--kind vertical` also renders the two QA-only mocks (`LiveUiMock`, `FeedUiMock`); skip `qaOnly` entries there, as `planPack` already refuses them (vertical kind, phase 1, 2026-10-29).
- The one-off render names every layout of `LiveFrameLoop` the same, `LiveFrameLoop-live-frame.<ext>`, so a second layout overwrites the first; a pack names them by `variant`, but `render:*` should add the layout (and the chat mode when it is not `open`) to the file name, decided with the vertical pack (phase 4).
- The chat's glow over the title counts the `strokeMargin` band as lit line: `chatGlowSources` (`src/overlays/chat/ChatLoop.tsx`) and the block's `contentGlowOpacity` (`src/overlays/block/legibility.ts`) blur the band from `shape` to `inner`, so with a 3 px margin they count 9 px of line instead of 6. It never underestimates and costs about one point (23 % against 22 %); fixing it needs the outline's outer edge in the layout. Leave it until a preset is refused because of it (Sticker Pop engine, phase C, 2026-11-21).
- `strokeMargin` with `strokeWidth: 0` is accepted: `refineStrokeMargin` (`src/overlays/shared/fields.ts`) reads only `strokeSides`, so the margin band is drawn with no line inside it. Refuse it with the way out, or document it as intended (Sticker Pop engine review, 2026-11-21).
- The side's refusal names only the depth when a bleed would also do: with a title bar filling the bleed (band 3, bar 24 + 6, `webcam-16x9`, bleed 32, depth 5) `refineSideHole` (`src/overlays/shared/side.ts`) says `use depth ≤ 0.`, without the `bleed ≥ 36` that also solves it; a sentence that offers `depth ≤ 0` alone reads as «turn the side off» (Sticker Pop engine, phase B and B fix reviews, 2026-11-22).
- A fill that is translucent by nature (`glass`, `fog`, `sparkles`) with `fillOpacity: 1` is not refused under a side: `refineSideFill` (`src/overlays/shared/side.ts`) reads only `fillOpacity`, so the side shows through (Sticker Pop engine, phase B review, 2026-11-22).
- A rectangular border whose radius is half its side (`webcam-square` with `radius: 200`) accepts the title bar and stops reading as a circle; with the buttons it falls into the corner refusal, without them it draws. Only `shape: circle` and `fit: screen` ignore the bar; no sold preset turns it on there. Decide whether a half-side radius ignores or refuses the bar (Sticker Pop engine, phase A review, 2026-11-21).
- `roundRectWithin` (`src/overlays/shared/side.ts`): the `spare < 0` branch (the inner shape rounder than the outer) never runs in the product, since the hole's radius is the window's + 2 and the copy's the window's + band + 1.5; only the unit test reaches it, from the right side, and two mutations of its left and bottom tests survive. Test it from all four sides (the circle moved 0.1 px each way in «side hole fits») or cut the branch and accept only `inner.radius <= outer.radius` (Sticker Pop engine, phase B fix review, 2026-11-22).
- `roundRectWithin` reads `radius` without `clampRadius`, unlike `roundRectSdf` and `roundRectPath`; every caller passes clamped shapes today, but an exported helper should clamp in its `core` (Sticker Pop engine, phase B fix review, 2026-11-22).
- `refineSideHole` rebuilds the outline (`offsetRoundRect(window, band)` plus `growTop`) instead of reading `geometry.layout.outer`; the two agree while the one-band refusal (`lines: 1`) runs first, and would part if the layout changed. At least a comment pointing to `layoutFrame` (Sticker Pop engine, phase B fix review, 2026-11-22).
